## ส่วน B — ชุดทดสอบ

รันจากโฟลเดอร์ [`../Submission-RAISE-M2-HW1/prototype/`](../Submission-RAISE-M2-HW1/prototype/):

```bash
npm install
npx playwright install chromium
npm test
```

ยิงไปที่ **เว็บจริงที่ deploy แล้ว** ไม่ใช่ไฟล์ในเครื่อง — เพราะเกณฑ์ผ่านข้อ ① และ ② วัดที่ระบบออนไลน์

| ข้อที่โจทย์กำหนด | เทสต์ | ต้อง login |
|---|---|---|
| ① เส้นทางหลัก — สร้างสูตรแล้วเห็นในรายการ | T1 | ✅ |
| ② ปุ่มเปลี่ยนสถานะ — ส่งตรวจแล้ว `draft` → `submitted` | T2 | ✅ |
| ③ กรอกไม่ครบแล้วต้องไม่บันทึก | T3 | ✅ |
| ④ 🔒 ไม่ล็อกอินแล้วอ่านข้อมูลไม่ได้ | T4a (UI เด้งไป login) · T4b (ยิง Firestore ตรง ๆ ถูกปฏิเสธ) | ❌ |
| ⑤ 🔒 บัญชีที่สองเปิดข้อมูลของบัญชีแรกไม่ได้ | T5a (REST) · T5b (sub-collection) · T5c (เปิด URL ตรง) | ✅ |
| **เพิ่มเอง** 🔒 คีย์ AI ต้องไม่หลุดขึ้นเว็บ | T6a (ไฟล์คีย์ต้อง 404) · T6b (ทุกไฟล์ที่เสิร์ฟต้องไม่มีคีย์) | ❌ |

### ⚠️ ขั้นตอนที่ต้องทำเองก่อนรันให้ครบ

เทสต์ที่ต้องเข้าสู่ระบบ (T1, T2, T3, T5) **ถูกข้ามอัตโนมัติ** จนกว่าจะใส่บัญชีทดสอบ —
ออกแบบแบบนี้โดยตั้งใจ เพื่อไม่ให้มีอีเมล/รหัสผ่านอยู่ในไฟล์ที่ commit ได้

```bash
cd ../Submission-RAISE-M2-HW1/prototype
cp tests/test-accounts.example.json tests/test-accounts.local.json
# แก้ไฟล์ .local.json ใส่บัญชี perfumer 2 บัญชี (สมัครที่ /signup.html ได้เลย)
npm test
```

**บัญชีทั้งสองต้องเป็น `perfumer` ทั้งคู่** — ถ้าบัญชี B เป็น `qc_reviewer` จะเห็นทุกสูตร
ตามสิทธิ์ที่ถูกต้อง แล้วเทสต์ T5 จะวัดการรั่วของข้อมูลไม่ได้ (เทสต์เช็กให้แล้วและจะฟ้องถ้าตั้งผิด)

`tests/test-accounts.local.json` ถูกกันไว้ใน [`../.gitignore`](../.gitignore) แล้ว

### รายงานผลถูกสร้างอัตโนมัติ

`npm test` เรียก [`tests/run.mjs`](../Submission-RAISE-M2-HW1/prototype/tests/run.mjs)

## ส่วน C — ความปลอดภัยของคีย์ AI (งานหลักของสัปดาห์นี้)

### สิ่งที่ตรวจพบ

ตรวจก่อน push ตามที่โจทย์กำหนด แล้วพบว่า **คีย์ OpenRouter ของหลักสูตรเปิดอ่านได้สาธารณะ**
ที่ `https://sattasarasada-perfume.web.app/config.local.js` (HTTP 200 เห็นคีย์เต็ม ๆ)

สาเหตุ: สัปดาห์ที่ 8 ตัดสินใจไว้ว่าจะยอมให้ `config.local.js` ถูก deploy ขึ้น hosting
เพื่อให้ปุ่ม AI ทำงานได้จริงบนเว็บสาธารณะ — `.gitignore` กันได้แค่ GitHub **ไม่ได้กันการ deploy**

### สิ่งที่แก้

| แก้อะไร | ที่ไหน |
|---|---|
| กัน `config.local.js` / `config.local.example.js` ออกจาก hosting | [`firebase.json`](../Submission-RAISE-M2-HW1/prototype/firebase.json) |
| ย้ายการหาคีย์มาไว้ที่เดียว: sessionStorage → ไฟล์ในเครื่อง → ถามผู้ใช้ | [`public/ai-key.js`](../Submission-RAISE-M2-HW1/prototype/public/ai-key.js) |
| ปุ่ม AI ทั้งสองจุดเรียกผ่าน `getOpenRouterKey()` แทน import คีย์ตรง ๆ | `formula-new.html`, `formula-detail.html` |
| ลืมคีย์อัตโนมัติเมื่อ OpenRouter ตอบ 401/403 | `forgetOpenRouterKey()` |
| deploy ใหม่ + เทสต์อัตโนมัติกันไม่ให้พลาดซ้ำ | T6a / T6b |

ยืนยันแล้วว่า `/config.local.js` ตอบ **404** ทั้งบนโดเมน `.web.app` และ `.firebaseapp.com`

### สิ่งที่ยังต้องทำต่อ

คีย์ยังไปถึงเบราว์เซอร์ผู้ใช้อยู่ดี (ผู้ใช้วางคีย์ของตัวเอง) — ทางแก้จริงคือย้ายไปฝั่งเซิร์ฟเวอร์
บันทึกไว้เป็นข้อแรกใน [`../BACKLOG.md`](../BACKLOG.md) แล้ว
และ **คีย์เดิมที่เคยเปิดสาธารณะต้องถือว่าใช้ไม่ได้แล้ว — ต้องแจ้งผู้สอนให้ออกคีย์ใหม่**
