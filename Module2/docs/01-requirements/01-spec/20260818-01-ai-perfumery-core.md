## 1. บริบท / ที่มา

การปรุงน้ำหอมในปัจจุบันต้องผสมสารกลิ่น 50–80 ชนิดเข้าด้วยกัน และแต่ละรอบการปรับสูตรเกิดปัญหาซ้ำๆ 3 อย่าง:

| ปัญหา | รายละเอียด | ผลกระทบ |
|---|---|---|
| **Scent Drift** (สูตรหลงทาง) | ปรับสัดส่วนไปมาจนกลิ่นหลุดจากบรีฟเดิมของลูกค้า โดยไม่รู้ว่าหลุดตอนไหน | รอบแก้ไขเพิ่มขึ้นไม่มีเพดาน |
| **Muddy Accord** (กลิ่นตีกัน) | สัดส่วนไม่สมดุล กลิ่นจับตัวเป็นกลิ่นแป้ง/สบู่ไร้มิติ | ทิ้งทั้งสูตร กลับไปตั้งต้นใหม่ |
| **Cost & IFRA Risk** | ต้องผสมจริง 50–80 รอบ และทุกครั้งที่แก้สารตัวหนึ่งต้องตรวจเพดาน IFRA ใหม่ทั้งสูตร | ต้นทุนสูง เสี่ยงผิดกฎหมาย |

**แนวทางแก้:** หลักการ **80/20** — AI รับผิดชอบการคำนวณโครงสร้างเคมี 80–90% ส่วนนักปรุงน้ำหอมเก็บงานศิลปะและการตัดสินใจเรื่องกลิ่นเฉพาะตัว 10–20%

**เป้าหมายเชิงตัวเลข:** ลดรอบผสมจริงในแล็บจาก ~70 ครั้ง เหลือ 3–5 ครั้ง

## 3. สถาปัตยกรรมหลักที่ข้อกำหนดทั้งหมดต้องยึด

```
Offline (ล่วงหน้า)                          Online (หน้างาน)
สารในคลัง → วิเคราะห์ฟิสิกส์เคมี             ผู้ใช้ป้อนสูตร
→ จัดกลุ่ม 100 Fixed Micro-Clusters         → ระบุกลุ่มของแต่ละสาร
→ คำนวณ Group Interaction Matrix            → ดึงน้ำหนัก % แต่ละกลุ่ม
→ เก็บเป็น "ช่วงข้อมูล" (Range) ใน DB        → คูณกับ Matrix ที่คำนวณไว้แล้ว
                                             → Fine-tune ด้วย Master Code รายสาร
                                             → คำนวณ Time-Series การระเหย
                                             → Engine B แปลงเป็นบรีฟ + เตือนความเสี่ยง
                                             → นักปรุงตัดสินใจนัวส์สุดท้าย
```

**กติกาบังคับ (ห้ามละเมิดในทุกข้อกำหนด):**
1. **Engine A** (Physics & Chemistry) คำนวณตัวเลขจริงเท่านั้น — ห้ามเดา
2. **Engine B** (Generative NLP) แปลผลเป็นภาษาเท่านั้น — **ไม่มีสิทธิ์สร้างหรือแก้ไขตัวเลข**
3. **Human-in-the-loop** — มนุษย์ตัดสินใจขั้นสุดท้ายเสมอ ระบบเป็น "เครื่องมือนำทาง" ไม่ใช่ "ผู้สร้างสรรค์แทน"

| FR-11 | คำนวณ Evaporation Shift | คำนวณการเปลี่ยนแปลงอัตราการระเหยเมื่อผสม (Azeotrope Effect) | สูง |

### 4.5 ความปลอดภัยและการปฏิบัติตามกฎ (Safety & Compliance)

| รหัส | ด้าน | ความต้องการ | ระดับ |
|---|---|---|---|
| NFR-01 | Performance | คำนวณสูตรที่มีสาร 50–80 ตัว จนได้ผลลัพธ์ครบ ต้องเสร็จภายใน **500 มิลลิวินาที** | สูง |
| NFR-02 | Performance | การตรวจ IFRA แบบ Real-time เมื่อผู้ใช้เปลี่ยนสัดส่วน ต้องตอบสนองภายใน **300 มิลลิวินาที** | สูง |

| NFR-09 | Security | สูตรของผู้ใช้ถือเป็นความลับทางการค้า ต้องเข้ารหัสขณะจัดเก็บ และแยกการเข้าถึงตามบัญชีอย่างเด็ดขาด | สูง |
| NFR-10 | Legal — พ.ร.บ.คอมพิวเตอร์ ม.26 | เก็บ Traffic Log การเข้าใช้งานอย่างน้อย **90 วัน** นับจากวันที่ข้อมูลเข้าสู่ระบบ | สูง |
| NFR-11 | Legal — PDPA | ขอความยินยอมก่อนเก็บข้อมูลส่วนบุคคล และรองรับสิทธิเจ้าของข้อมูล (รับรู้ / เข้าถึง / แก้ไข / ลบ / คัดค้านการประมวลผล) | สูง |
| NFR-12 | AI Ethics — Transparency | ต้องแจ้งผู้ใช้ชัดเจนว่าคำบรรยายกลิ่นสร้างโดย AI และต้องผ่านการยืนยันจากนักปรุงก่อนนำไปใช้จริง | สูง |
| NFR-13 | AI Ethics — Accountability | ต้องมี Fallback Plan เมื่อ Engine คำนวณผิดพลาด และระบุผู้รับผิดชอบผลลัพธ์ได้ชัดเจน | กลาง |
| NFR-14 | Usability | ผลสรุปหลัก (บรีฟกลิ่น + IFRA + ความเสี่ยง) ต้องอ่านได้ครบภายใน 1 หน้าจอโดยไม่ต้องเลื่อน | กลาง |
| NFR-15 | Accessibility | ค่าความต่างของสี (contrast ratio) ต้องผ่านเกณฑ์ WCAG 2.1 ระดับ AA เป็นอย่างน้อย | กลาง |

## 6. ขอบเขต (Scope)

### 6.1 สิ่งที่ทำ (In Scope)
- Master Code รายสาร + การจัดกลุ่ม Micro-Cluster
- Group Interaction Matrix แบบ "ช่วงข้อมูล" (Range) ที่คำนวณล่วงหน้า
- Engine A (คำนวณเคมี) + Engine B (บรรยายกลิ่น) + Olfactory Threshold Filter
- ตรวจ IFRA Compliance และ Muddy Accord Detection
- Dashboard แสดงผลพร้อม Command Bar และ What-If Simulation
- ระบบบัญชีผู้ใช้ + Audit Log + การจัดการความยินยอม

### 6.2 สิ่งที่ไม่ทำในรอบนี้ (Out of Scope)
- ระบบสั่งซื้อวัตถุดิบ / เชื่อมต่อ Supplier
- ระบบจัดการสต็อกวัตถุดิบในโกดัง
- การผลิตจริง / เชื่อมต่อเครื่องผสมอัตโนมัติในโรงงาน
- การขึ้นทะเบียน อย. อัตโนมัติ (ระบบแค่เตรียมข้อมูลให้ ไม่ยื่นแทน)
- โมดูลมาตรฐานข้ามโดเมน (Cross-Domain Standards) — รอบนี้โฟกัสเฉพาะมาตรฐานด้านน้ำหอม/เครื่องสำอางเท่านั้น

## 7. Business Rules

- **BR-01** ผลรวมสัดส่วนของสูตรต้องเท่ากับ 100% จึงจะคำนวณได้
- **BR-02** สูตรที่ตรวจ IFRA แล้วได้ผล FAIL ห้ามส่งออกเป็นรายงานฉบับสมบูรณ์ จนกว่าจะแก้ให้ PASS
- **BR-03** สารที่มีความเข้มข้นต่ำกว่าค่า ODT จะไม่ถูกนำไปเขียนบรีฟกลิ่น แต่ยังคงถูกนับในการคำนวณ IFRA และต้นทุน
- **BR-04** เกณฑ์ Muddy Accord: ถ้า**ไม่มี**กลุ่มใดมีสัดส่วน > 20% **และไม่มี**กลุ่มใดต่ำกว่า 5% ให้ถือว่าเข้าข่ายเสี่ยง
- **BR-05** Engine B ห้ามระบุตัวเลขใดๆ ที่ไม่ได้มาจาก output ของ Engine A
- **BR-06** ทุกผลลัพธ์เป็น "ข้อเสนอแนะ" — การอนุมัติสูตรขั้นสุดท้ายต้องมาจากนักปรุงน้ำหอมที่เป็นมนุษย์เสมอ

## 8. ข้อพิจารณาด้านกฎหมาย IT และ PDPA

- ระบบมีการเข้าสู่ระบบและเก็บ Log การใช้งาน จึงเข้าข่าย **พ.ร.บ. ว่าด้วยการกระทำความผิดเกี่ยวกับคอมพิวเตอร์ มาตรา 26** ต้องเก็บ Traffic Log อย่างน้อย 90 วันตั้งแต่ขั้นออกแบบระบบ (→ NFR-10)
- ข้อมูลบัญชีผู้ใช้ (ชื่อ, อีเมล, IP Address) เป็น **ข้อมูลส่วนบุคคล (PII)** ตาม PDPA ต้องขอความยินยอมและรองรับสิทธิเจ้าของข้อมูล (→ NFR-11, FR-39)
- **สูตรน้ำหอมของผู้ใช้ = ความลับทางการค้า** ไม่ใช่ข้อมูลส่วนบุคคลโดยตรง แต่มีมูลค่าสูงมาก ต้องแยกสิทธิ์การเข้าถึงเข้มงวด (→ NFR-09)
- หากในอนาคตมีการส่งข้อมูลสูตรไปประมวลผลผ่าน LLM ภายนอก ต้องทำ **Data Minimization** และตรวจสอบว่าผู้ให้บริการไม่นำข้อมูลไป Train ต่อ (Opt-out of Model Training)
- ตามหลักจริยธรรม AI ต้องแจ้งผู้ใช้ว่ากำลังอ่านผลลัพธ์ที่สร้างโดย AI (→ NFR-12)
- *หมายเหตุ: เนื้อหาส่วนนี้เป็นข้อพิจารณาระดับ requirement ไม่ใช่คำปรึกษาทางกฎหมายที่เป็นทางการ*
