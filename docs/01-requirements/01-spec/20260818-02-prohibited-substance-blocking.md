# เพิ่มข้อกำหนด: บล็อก/เตือนสารต้องห้าม (IFRA PROHIBITION) ตั้งแต่จุดค้นหา/เลือกสาร

- **วันที่สร้าง:** 2026-08-18
- **เลขที่เอกสาร:** 20260818-02
- **สถานะ:** Draft
- **แหล่งที่มา:** ค้นพบระหว่างสร้างสูตรตัวอย่างจากคลังวัตถุดิบจริง (ดู [[../../05-log/20260818-log|Log 2026-08-18]] หัวข้อ 7 และหัวข้อ 11) — พบสารสถานะ **PROHIBITION** 3 ตัวในคลังวัตถุดิบ (6-methyl Coumarin, Musk Ambrette, Musk Xylol) ที่ไม่มี FR ใดรองรับการเตือน/บล็อกก่อนเข้าสูตร
- **ขยายจากเอกสาร:** [[20260818-01-ai-perfumery-core]] หมวด 4.1 (FR-03) และหมวด 4.5 (Compliance — FR-21, FR-22)

## 1. บริบท / ช่องว่างที่พบ

[[20260818-01-ai-perfumery-core|เอกสาร spec หลัก]] มี FR-21 (ตรวจเพดาน IFRA แบบ Real-time) และ FR-22 (แสดง PASS/FAIL) แต่ทั้งสองข้อเป็นการตรวจ **หลังจากคำนวณทั้งสูตรเสร็จแล้ว** (post-hoc ceiling check) และครอบคลุมเฉพาะสารประเภท **RESTRICTION** (มีเพดาน % ที่อนุญาต) เท่านั้น

ไม่มี FR ใดอนุญาตหรือกำหนดพฤติกรรมการเตือน/บล็อกสารประเภท **PROHIBITION** (ห้ามใช้เด็ดขาดไม่ว่าปริมาณเท่าไร) ตั้งแต่ขั้นตอนค้นหา/เลือกสาร (FR-03) — ก่อนที่สารนั้นจะถูกเพิ่มเข้าสูตรเลย ช่องว่างนี้ถูกยืนยันจากข้อมูลจริง: ระหว่างสร้างสูตรตัวอย่าง พบสาร 3 ตัวในคลังที่มีสถานะ PROHIBITION ตาม IFRA 51st Amendment แต่ระบบ (ตามที่ออกแบบไว้ปัจจุบัน) จะปล่อยให้ผู้ใช้เพิ่มสารเหล่านี้เข้าสูตรได้ตามปกติ แล้วไปพบปัญหาเอาตอนรอผลคำนวณเสร็จเท่านั้น

ทางฝั่งข้อมูล `db-spec.md` ได้ออกแบบ `RegulatoryLimit.limit_type` ให้รองรับ PROHIBITION ไว้ล่วงหน้าแล้ว (ดู D-09 ใน Log หัวข้อ 11) แต่ยังไม่มี FR กำกับพฤติกรรม UX ว่าต้องเตือน/บล็อกที่จุดใด — เอกสารนี้จึงเพิ่ม FR ใหม่เพื่ออุดช่องว่างนี้

## 2. ข้อกำหนดเชิงฟังก์ชันใหม่ (Functional Requirements เพิ่มเติมต่อ [[20260818-01-ai-perfumery-core]] §4.5)

> ระดับความสำคัญกำหนดร่วมกับผู้ใช้จริง: เนื่องจาก PROHIBITION คือข้อห้ามทางกฎหมายแบบ zero-tolerance (ต่างจาก RESTRICTION ที่ยังมีเพดานให้ใช้ได้) และ `CLAUDE.md` กำหนดให้ IFRA Compliance เป็นข้อบังคับที่ต้องมี NFR/AC กำกับเสมอ จึงกำหนดเป็นระดับ **สูง (MVP)** ทั้งสองข้อ

| รหัส | ความต้องการ | รายละเอียด | ระดับ |
|---|---|---|---|
| FR-40 | แสดงสถานะสารต้องห้ามในผลค้นหา | เมื่อผู้ใช้ค้นหา/เรียกดูสารผ่าน FR-03 ระบบต้องตรวจสถานะ Regulatory Limit ของสารนั้นทันที และแสดง badge/ป้ายสถานะ **"ห้ามใช้ (PROHIBITION)"** เด่นชัดในผลลัพธ์ค้นหาทุกรายการที่เข้าเกณฑ์ พร้อมเหตุผลอ้างอิง (เลข IFRA Amendment/มาตรา) — ต้องแสดง**ก่อน**ที่ผู้ใช้จะกดเลือกสารนั้นเข้าสูตร | สูง |
| FR-41 | บล็อกการเพิ่มสารต้องห้ามเข้าสูตร | ระบบต้องปฏิเสธการเพิ่มสารที่มีสถานะ PROHIBITION เข้าสู่สูตรโดยเด็ดขาด **ไม่มี override** พร้อมแสดงข้อความเหตุผลอ้างอิงเลข IFRA Amendment/มาตราที่เกี่ยวข้อง — พฤติกรรมนี้แตกต่างจากสารสถานะ RESTRICTION (FR-21/FR-22) ที่ยังอนุญาตให้เพิ่มเข้าสูตรได้แต่ต้องผ่านการตรวจเพดานภายหลัง | สูง |

**ความสัมพันธ์กับ FR เดิม:** FR-40/FR-41 ทำงาน**ก่อน** FR-21/FR-22 เสมอ (จุดค้นหา/เลือกสาร ไม่ใช่จุดคำนวณสูตรเสร็จ) ทั้งสองชุดไม่ทดแทนกัน — FR-21/FR-22 ยังจำเป็นสำหรับตรวจสารประเภท RESTRICTION ที่ผ่านเข้าสูตรมาแล้ว

## 3. Business Rule เพิ่มเติม

- **BR-07** สารที่มีสถานะ Regulatory Limit เป็น PROHIBITION ห้ามถูกเพิ่มเข้าสูตรโดยเด็ดขาด ไม่มีข้อยกเว้นหรือกลไก override ใดๆ ในระบบ (ต่างจากสถานะ RESTRICTION ที่ยังมีเพดาน % ให้ใช้ได้ตาม BR-01/BR-02)
